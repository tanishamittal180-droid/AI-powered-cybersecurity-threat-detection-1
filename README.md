# SentinelAI — AI-Powered Cybersecurity Threat Detection System

A beginner-friendly, GitHub-ready cybersecurity analytics lab that uses **synthetic network telemetry**, a Random Forest classifier, Isolation Forest anomaly detection, a Flask API, and a responsive web dashboard. It is designed for education, portfolio demonstrations, and safe virtual simulation—not as a production security product.

## Features

- **Responsive SOC-style dashboard** with event totals, threat rate, high-severity counts, and model metrics.
- **Synthetic traffic generator** to safely simulate normal and suspicious network patterns without attacking any system.
- **Supervised detection** using a Random Forest classifier, including accuracy, precision, recall, F1, and confusion matrix.
- **Unsupervised anomaly detection** using Isolation Forest as a second signal.
- **Single-event analysis form** with threat probability, severity, and an anomaly flag.
- **Batch simulation** with adjustable event count and a filterable event stream.
- **CSV workflow:** upload labeled data to retrain, or upload unlabeled feature rows to score them.
- **Export** the current event stream as CSV; prediction batches are saved under `outputs/`.
- **REST endpoints** for health, summary, event stream, simulation, prediction, metrics, and upload.
- **Local-first demo:** no API keys, cloud account, GPU, or real network access required.

## Important scope and limitations

The included data is generated by code and is intentionally artificial. High scores on synthetic data do **not** demonstrate real-world detection performance. Real deployments require a carefully validated public or organization-approved dataset, time-aware testing, drift monitoring, access controls, logging, privacy review, and human investigation. The dashboard is a local demonstration and should not be exposed directly to the public internet. The `/api/simulate` route creates benign synthetic records; it does not generate attack traffic or perform network actions.

## Quick start — Windows PowerShell

Install Python 3.10–3.12 and Git. Open a terminal in the project folder:

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -r requirements.txt
python -m src.data_generator
python main.py train
python -m src.webapp
```

Open **http://127.0.0.1:5000** in your browser. Keep the terminal running while using the dashboard. If PowerShell blocks activation, use `Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass` for the current terminal only, then activate again.

## CLI commands

Run from the project root after activating the environment:

```bash
python main.py generate-data                 # create sample synthetic CSV
python main.py train                         # train both models and save metrics
python main.py demo --rows 100               # generate and score a fresh demo batch
python main.py predict-sample                # score the sample CSV feature columns
python main.py predict-sample --input path/to/traffic.csv
```

The web app bootstraps the sample dataset and trains models automatically if model files are missing. `python main.py train` is useful when you want to explicitly retrain and view metrics.

## Input data format

Required numeric columns:

| Column | Meaning in this educational dataset |
|---|---|
| `packet_size` | Approximate packet size in bytes |
| `failed_logins` | Count of failed login attempts in an observation window |
| `request_frequency` | Request count/rate proxy for a fixed observation window |
| `connection_duration` | Connection duration proxy |
| `bytes_out` | Outbound bytes proxy |
| `unique_ports` | Count of distinct destination ports observed |
| `protocol_encoded` | Example encoding: 0=TCP, 1=UDP, 2=other |
| `label` | Optional training label: 0=normal, 1=threat |

These are simplified synthetic features, not a canonical schema for CICIDS, UNSW-NB15, or NSL-KDD. Those datasets have different columns and labels; map them explicitly before uploading. Do not upload sensitive or unauthorized data.

## API examples

Health check:

```bash
curl http://127.0.0.1:5000/api/health
```

Predict one event (PowerShell users can use `curl.exe` or the dashboard form):

```bash
curl -X POST http://127.0.0.1:5000/api/predict   -H "Content-Type: application/json"   -d '{"packet_size":1250,"failed_logins":5,"request_frequency":90,"connection_duration":2,"bytes_out":6500,"unique_ports":7,"protocol_encoded":0}'
```

Generate ten safe simulated events:

```bash
curl -X POST http://127.0.0.1:5000/api/simulate -H "Content-Type: application/json" -d '{"count":10}'
```

Other endpoints: `GET /api/summary`, `GET /api/events`, `GET /api/metrics`, `POST /api/upload`.

## Troubleshooting

- **`python` not found:** install Python and enable “Add Python to PATH”; on Windows try `py`.
- **PowerShell activation blocked:** run `Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass` in that terminal.
- **Missing columns on upload:** use the exact seven feature names shown above.
- **Training needs both labels:** labeled training CSV must include at least 20 usable rows and both 0 and 1 in `label`.
- **Dashboard chart not visible offline:** Chart.js is loaded from a CDN, so the chart requires internet access; the API and ML pipeline run locally.
- **Port 5000 busy:** stop the other process or change the port at the bottom of `src/webapp.py`.

## Responsible use

Use only public datasets or data you have permission to analyze. This project is a learning prototype; it does not inspect live packets, block traffic, identify real people, or replace a SIEM/IDS. Validate any future model against representative data before using it for decisions.

### One-command launcher scripts

- Windows: double-click `run_windows.bat` or run `.\run_windows.bat` from the project folder. It creates the virtual environment if needed, installs dependencies, trains the models, and starts the local dashboard.
- macOS/Linux: run `chmod +x run_unix.sh` once, then `./run_unix.sh`. This also installs dependencies and starts the dashboard.

The first launch needs an internet connection to install Python packages. The dashboard's chart library and web fonts are loaded from CDNs; those visual assets require internet access, while the Python detection pipeline itself runs locally.
